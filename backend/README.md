# LungCare AI external service

This Python service is separate from the managed TanStack frontend. It cannot run inside Lovable's frontend hosting. No model, MongoDB credentials, deployed Flask URL, or training notebook was supplied. No inference or clinical validity is claimed.

## Deploy and connect

1. Provision MongoDB Atlas (or a secured MongoDB replica set). Create a least-privilege application database user, restrict network access to your hosting server, require TLS, and store the connection URI only in the backend environment as `MONGODB_URI`. Transactions are required: standalone MongoDB fails closed rather than making partial clinical-demo state changes.
2. Use Linux x86_64, Python 3.10 for the initial TF 2.10 compatibility baseline. `python -m venv .venv`, activate it, then `pip install -r requirements.txt`. Dependencies are pinned to the previously reported TensorFlow/Keras 2.10 family, not verified against the absent model. Check the artifact before changing versions. Local tests here ran without TensorFlow in a separate Python environment; they do not validate the production ML dependency set.
3. Copy `.env.example` to a private `.env` on your server, never commit it. Generate `SECRET_KEY` through your hosting provider's secure secret generator (32+ characters). Set MongoDB URI/database, exact frontend HTTPS origin, writable private upload/report paths, maximum MB, and session settings.
4. Transfer the complete actual `lung_cancer_saved_model` directory to the server, preserving `saved_model.pb`, `variables/`, and `assets/`. The Windows path is not accessible remotely. Set `AI_MODEL_PATH` to its server path.
5. Inspect the actual signature in a Python 3.10 environment: `python -c "import tensorflow as tf, os; m=tf.saved_model.load(os.environ['AI_MODEL_PATH']); print(m.signatures['serving_default'].structured_input_signature); print(m.signatures['serving_default'].structured_outputs)"`. Inspect training code for exact class order, color conversion, interpolation, normalization, dtype, and output semantics. Fill a separate manifest from `model-manifest.example.json`; set `verified_from_training` true only after verification. Set `MODEL_MANIFEST_PATH` and `MODEL_VERSION`. Current adapter supports RGB/BGR/grayscale and explicit none/divide_255/minus_one_one preprocessing; other training pipelines must be implemented from the training source. A confirmation flag alone is not evidence of correctness. Compare inference with the original project using representative CT slices before use.
6. Run `python manage.py init-db`. This creates unique email, prediction-per-case, review-per-case, report-per-case, scheduler-job-key indexes and session/rate-limit expiry indexes. Run `python manage.py seed-doctors` to securely provision Doctor A, B, and C using interactive real emails and passwords. Existing matching accounts are preserved. Run `python manage.py create-admin` for the coordinator. No default credentials exist.
7. Run `gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 --timeout 180 wsgi:app` behind HTTPS on a Python/container host with a persistent private disk. Docker: `docker build -t lungcare-api .`; mount model read-only and `/data` writable, provide backend secrets through host settings. Do not put secrets in image layers or use ephemeral storage for patient files. Multiple processes load separate model instances; size memory accordingly.
8. Run `python worker.py` as a **separate managed worker** using the same environment. It retries every minute and opens each durable two-hour slot once. It assigns awaiting cases and reminds doctors; it never generates assessments or automatically signs reviews. Transactions and unique job keys make simultaneous workers safe. MongoDB retains completed session/next-run records and scheduler error types. `python manage.py run-session` manually executes the current slot. Verify persisted completion before calling the scheduler operational. Use `python manage.py recover-processing` after a worker crash to reset cases stuck beyond 30 minutes, with no saved prediction.
9. Fetch the real hosted `/health`, then set the frontend `VITE_API_BASE_URL` to that verified HTTPS address and `VITE_APP_NAME=LungCare AI`. Configure `FRONTEND_ORIGIN` exactly to the frontend's actual origin. Publish/redeploy the frontend after changing public environment settings. **Do not invent an API address.** Managed file routing supplies deep-link handling; no React Router fallback installation is needed.
10. Prefer frontend and API subdomains under the same site (or a same-site reverse proxy). Cookies are HttpOnly, expiring, revocable, and Secure in production. Cross-site use requires `SameSite=None; Secure` and credentialed CORS, but third-party-cookie restrictions can still block access. Unsafe requests require the exact allowed Origin and custom header; only that origin is allowed to preflight. Local HTTP development requires `COOKIE_SECURE=false`, `COOKIE_SAMESITE=Lax`, and the exact local origin. Never disable these production checks. Rate limits use MongoDB-backed 15-minute counters; configure trusted reverse proxy routing without accepting client-controlled forwarding headers.
11. Run `pytest -q tests` and the full live acceptance flow using actual database, accounts, CT images and model; verify records read back in the UI. Tests bundled here cover fail-closed inference, probability validation, status rules, health, signed-out access, missing MongoDB, and origin verification. They do **not** prove ownership/transaction concurrency/PDF/auth success end-to-end in absence of a live database.

## Grad-CAM limitation

The absent SavedModel's feature maps and gradients cannot be inspected. `serving_default` alone does not establish a differentiable intermediate convolutional-layer path. The adapter intentionally returns `gradcam_status=unavailable` rather than fabricate a heatmap. Supply the actual training architecture or a differentiable feature-map export to implement and test true Grad-CAM. Reports preserve this limitation. Prediction remains valid if explanation is unavailable.

## Dependency health and final repairs

`GET /health` is process liveness with separate dependency results. HTTP 200 does not mean inference is operational. `GET /health/ready` returns HTTP 503 unless MongoDB ping, an actual read-only transaction (aborted without writes), writable private directories, and model loading all succeed. No patient records or credentials are returned. The Docker health check uses readiness; some hosts require configuring their health path separately. Model readiness verifies loading, not representative-image accuracy or clinical validity.

`MONGODB_TLS=true` is now explicitly enforced in production. For an explicitly local HTTP development replica set only, set `COOKIE_SECURE=false`, `COOKIE_SAMESITE=Lax`, and `MONGODB_TLS=false` when that local set has no TLS. All database workflows reject standalone topology before accessing application collections. Transaction authorization is further verified by readiness and actual transactional operations. Secure doctor provisioning inserts the account and doctor record in one transaction.

All five `manage.py` commands listed above exist; `--help` is executable without service configuration. Their successful database effects, the production ML dependency installation, Docker image, and worker execution still require the external environment and have not been verified here. Existing account data is not replaced by provisioning.

## Security and lifecycle

Private access is checked server-side for patient ownership, current assigned doctor, or coordinator. User-submitted roles are ignored. Images are validated by Pillow decoding and privately named with ObjectIds; report paragraphs are escaped. No private data is stored in browser storage. JSON/image/report responses should be served no-store; back up MongoDB and private storage together. Configure retention/deletion and documented consent before collecting real patient data. Audit/provisioning security, password resets, transactional failure recovery, rate-limit proxy behavior, and clinically representative validation require a live deployment review. This is an academic prototype, not production clinical software.
